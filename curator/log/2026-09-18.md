## Learnings
- **`curator/sources.json` was invalid JSON for at least two weeks and no run noticed.** Every daily run reads this file as its beat, but reads it by eye, so a parse error is silent. Worth a one-line `python3 -c "import json;json.load(open('curator/sources.json'))"` guard at the top of each run — it costs nothing and would have caught this on 2026-09-04. Root cause: raw `"` around an event title inside a `note` string; use single quotes there.
- **Three long-running watches were closed this run using arithmetic, not searches.** BUEN KARMA (Dec 7 2026 = Monday, not Saturday) and DJ RHYTHM (Oct 6 2026 = Tuesday, not Sunday) were both killed against snippets already recorded in prior logs — no new query needed. The day-of-week kill should be applied to a snippet the moment it is *recorded*, not deferred to the watch window; deferring scheduled two pointless future searches. Check the weekday before adding anything to the watch list.
- **The MANTRA DANZA Aug 29 saga cost roughly five runs of searching and the answer was a past July event.** The Aug 23 neutral-query rule worked exactly as designed here and gave a clean, internally consistent verbatim date on the first try. Apply it as the *first* query on any date-uncertain event rather than after a date-framed query has already anchored the summariser.
- **Predicted slug patterns are not evidence.** The SUPERMOON anniversary slugs differ per edition and per TLD. Treating a guessed slug's absence as "no event" is a false negative; prefer the first-party domain when one exists.
